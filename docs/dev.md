# Dev Guide

## 启动

- 安装依赖：`pnpm install`
- 开发运行：`pnpm tauri dev`
- Windows 侧依赖 `package.json` 中的 `pnpm exec tauri` 脚本桥接本地 CLI；若 `node_modules` 为空，先重新执行 `pnpm install`

## 回归验证清单（M0）

- macOS 与 Windows 两端都能启动应用
- 同一端只允许一个应用实例；重复打开会聚焦已有窗口，避免第二个窗口因 `32910` 端口占用而显示“已停止”
- 设置页能修改 `max_item_bytes` 并落盘（重启后仍生效）
- 多台设备设置相同 `shared_code` 并点击“保存配置”后，会加入同一共享域
- 可通过界面上的“刷新”触发一次状态刷新和补充扫描；日常成员列表由后台 UDP 心跳、mDNS 和真实 TCP 收发信号持续维护
- 本机剪贴板变化会通过监听器入发送队列，不再依赖同步主循环轮询读取
- 剪贴板监听器内部使用 `50ms` 检测间隔，主同步循环空闲间隔为 `10ms`；界面不再暴露旧版轮询间隔配置
- TCP 内容同步使用长度前缀二进制帧；图片和文件 bundle 在协议内保持 raw bytes，不再被 JSON/base64 放大
- 发送队列在发现列表暂时为空、或只送达部分成员时，会自动短退避重试，不会首轮失败就直接丢弃
- 状态区“共享域成员（含本机）”会把当前设备也计入人数；只要本机已有设备 ID，最小值就是 1
- 共享域成员列表的第一行固定展示本机；展开本机行后显示同共享码下发现的其他共享域成员
- 远端成员信号来自 UDP 广播心跳、mDNS 发现、真实收到的设备 ID、真实发送成功的地址，以及手动配置的兜底地址
- UI 会定时读取运行时成员缓存；不再只有点击“刷新”才更新成员列表
- 扫描提示文案与成员列表分离渲染，重复点击“刷新”不会因为 DOM 被替换而卡在“扫描中”
- 剪贴板读取会优先尝试平台文件列表，再尝试平台图片，最后才尝试文本，避免“复制非文字但被文本描述抢先命中”
- 复制 Finder / Explorer 中的文件或目录时，会优先识别文件列表；Windows 文件列表读取使用原生 `CF_HDROP`，不再依赖 PowerShell 子进程
- Windows 截图/图片读取优先使用原生 `PNG` 注册格式；若不存在，再尝试 `CF_DIBV5 / CF_DIB`，最后尝试 `CF_BITMAP`
- Windows 接收图片时直接写入原生 bitmap，避免先经通用后端转换导致粘贴可用性变慢
- 复制带格式内容时，会优先识别 `HTML`，再识别 `RTF`，最后才退回纯文本
- 剪贴板读写都带短重试；Windows 剪贴板被别的进程短暂占用时，不会一次失败就丢掉本次同步
- 图片按原始 PNG 字节做大小限制；超限时会先自动等比缩小，再用快速 PNG 压缩重编码后发送
- 文件/目录会先打成 `tar` bundle 再传输，远端解包到临时目录后再写回文件列表剪贴板
- 传输进度会区分直接复制文字、HTML 富文本、RTF 富文本与文件；文本类内容会显示预览，较长内容可在进度卡片内展开查看，刷新进度时保留预览区滚动位置；用户正在悬停、聚焦或滚动预览内容时会短暂停止重绘，避免 macOS WebView 惯性滚动被打断
- TCP 写超时会按实际发送 payload 大小动态放宽，避免图片在固定短超时内被误判失败
- 本机变化与远端变化都走队列顺序处理；多设备同时复制时，按 `created_at_ms + source_device_id` 做稳定收敛
- 启用加密时，默认使用 `shared_code` 派生密钥；若共享域内设备设置相同自定义 `pairing_code`，也应正常同步
- 共享域内设备的 `shared_code` 或 `pairing_code` 不一致时，同步失败且日志出现解密失败提示
- 页面设置变更不会自动保存；所有可编辑项集中在“同步配置”区域，点击“保存配置”后统一落盘、重启同步并刷新状态
- 复制文本：另一端收到并写入剪贴板（已实现基础防回环）
- 复制图片：另一端收到并写入剪贴板（超限会被阻止）
- 复制文件/目录：另一端收到后可直接粘贴为文件/目录，而不是只剩名字或路径文本
- 复制常见富文本：另一端应尽量保留 `HTML / RTF` 格式，而不是只剩纯文本

## M0 测试态参数（建议）

- `max_item_bytes`：测试态 `65536`（便于构造超限用例）

## 常见联调问题

- 显示“已停止”：检查运行日志是否有端口占用、权限或网络监听错误；修改配置后需要点击“保存配置”
- 日志出现 `listener bind failed: Address already in use`：说明已有另一个实例或旧进程占用了同步端口；当前版本会通过单实例插件避免正常重复打开，开发时需要先结束旧的 `pnpm tauri dev` 或旧打包 App
- 一端有错误：查看“最近错误”，常见是端口被占用或兜底地址不可达
- 复制无反应：先确认共享域内设备的 `shared_code` 完全一致，再检查这些设备是否都已启动应用，以及防火墙是否允许监听端口入站
- 日志出现 `outbound item ... pending peers`：说明当前这条复制事件正在等成员发现或重试，不代表已经彻底失败
- 日志出现 `apply retry queued`：说明远端系统剪贴板短时忙碌，当前版本会自动补重试
- 日志出现 `write peer failed ... timeout_ms=...`：说明这次 TCP 写入未完成，图片场景优先检查内容大小、网络质量和防火墙拦截
- 日志出现 `detected local clipboard kind=... size_bytes=...`：说明本机已识别到一次剪贴板事件；若 Windows 复制图片/文件仍显示 `text`，优先定位源应用是否只写入了文本格式
- 日志出现 `received item ... kind=...` 但没有 `applied item ...`：说明网络已到达，下一步看接收端写剪贴板错误或重试日志
- 双端运行日志会同步落盘到系统临时目录的 `lan-clipboard/runtime.log`；macOS 通常在 `/var/folders/.../T/lan-clipboard/runtime.log`，Windows 通常在 `%TEMP%\\lan-clipboard\\runtime.log`
- Windows 截图仍不同步：优先看日志里是否出现 `detected local clipboard kind=image_png`；如果没有，说明源应用提供的是尚未覆盖的 Windows 私有格式
- 复制文件后仍只剩名字：说明该次复制没有被系统识别成文件列表，而是退化成了纯文本；优先确认是从 Finder / Explorer 的文件面板直接复制，而不是从终端或编辑器复制路径文本
- 富文本贴过去只剩纯文本：先确认源应用确实把 `HTML / RTF` 放进了系统剪贴板；某些应用只暴露私有格式时，当前版本仍会回退成纯文本
- 扫描不到设备：确认共享域内设备都打开应用，且路由器/AP 未阻止组播或 UDP 广播；防火墙需允许 TCP `32910` 与 UDP `32911`
- 日志提示 `decrypt failed`：共享域内设备的 `shared_code` 不一致，或某端设置了额外 `pairing_code` 但其他设备没有同步该值
- 日志提示 `received plain frame but encryption enabled`：双方加密开关不一致
- 日志提示 `unsupported wire version`：说明两端不是同一套二进制协议版本，需要两端都重启到最新构建
- 若历史版本扫描设备时反复出现 `mdns_sd::service_daemon ... closed channel`，更新到当前版本；当前扫描流程已改为先 `stop_browse` 再 `shutdown`
