# Dev Guide

## 启动

- 安装依赖：`pnpm install`
- 开发运行：`pnpm tauri dev`
- Windows 侧依赖 `package.json` 中的 `pnpm exec tauri` 脚本桥接本地 CLI；若 `node_modules` 为空，先重新执行 `pnpm install`

## 回归验证清单（M0）

- macOS 与 Windows 两端都能启动应用
- 设置页能修改 `max_item_bytes` 并落盘（重启后仍生效）
- 多台设备设置相同 `shared_code` 并点击“保存配置”后，会加入同一共享域
- 可通过界面上的“刷新”触发一次状态刷新和补充扫描；日常成员列表由后台 UDP 心跳、mDNS 和真实 TCP 收发信号持续维护
- 状态区“共享域成员（含本机）”会把当前设备也计入人数；只要本机已有设备 ID，最小值就是 1
- 远端成员信号来自 UDP 广播心跳、mDNS 发现、真实收到的设备 ID、真实发送成功的地址，以及手动配置的兜底地址
- UI 会定时读取运行时成员缓存；不再只有点击“刷新”才更新成员列表
- 扫描提示文案与成员列表分离渲染，重复点击“刷新”不会因为 DOM 被替换而卡在“扫描中”
- 启用加密时，默认使用 `shared_code` 派生密钥；若共享域内设备设置相同自定义 `pairing_code`，也应正常同步
- 共享域内设备的 `shared_code` 或 `pairing_code` 不一致时，同步失败且日志出现解密失败提示
- 页面设置变更不会自动保存；所有可编辑项集中在“同步配置”区域，点击“保存配置”后统一落盘、重启同步并刷新状态
- 复制文本：另一端收到并写入剪贴板（已实现基础防回环）
- 复制图片：另一端收到并写入剪贴板（超限会被阻止）

## M0 测试态参数（建议）

- `poll_interval_ms`：测试态 `500`，默认 `900`
- `max_item_bytes`：测试态 `65536`（便于构造超限用例）

## 常见联调问题

- 显示“已停止”：检查运行日志是否有端口占用、权限或网络监听错误；修改配置后需要点击“保存配置”
- 一端有错误：查看“最近错误”，常见是端口被占用或兜底地址不可达
- 复制无反应：先确认共享域内设备的 `shared_code` 完全一致，再检查这些设备是否都已启动应用，以及防火墙是否允许监听端口入站
- 扫描不到设备：确认共享域内设备都打开应用，且路由器/AP 未阻止组播或 UDP 广播；防火墙需允许 TCP `32910` 与 UDP `32911`
- 日志提示 `decrypt failed`：共享域内设备的 `shared_code` 不一致，或某端设置了额外 `pairing_code` 但其他设备没有同步该值
- 日志提示 `received plain frame but encryption enabled`：双方加密开关不一致
- 若历史版本扫描设备时反复出现 `mdns_sd::service_daemon ... closed channel`，更新到当前版本；当前扫描流程已改为先 `stop_browse` 再 `shutdown`
