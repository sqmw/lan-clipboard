# Security

## 当前安全基线

- 目标版本：应用 `2.0.1`，线协议 `v5`。
- 兼容性：`v5` 与旧 `v4` 不互通，不提供降级或明文 fallback。
- 网络假设：局域网不可信；发现包、连接来源、帧长度、归档内容和展示字段都属于外部输入。
- 信任单位：持有同一配对密钥的设备属于同一个共享域。当前是群组级认证，不是逐设备证书体系。

## 配对密钥

- 新配置由应用生成 `26` 位 Base32 配对密钥，字符集排除了易混淆字符，理论随机空间约 `130 bit`。
- 后端始终做格式与弱模式校验；全相同字符、字符种类过少和短周期重复值会被拒绝。
- 配对密钥只能复制到可信设备，不应手工改成可记忆口令。
- `v5` 握手是高熵 PSK 协议，不是 PAKE。若使用可猜口令，握手 transcript 会允许离线猜测，因此禁止弱密钥是协议安全前提。

## 发现与认证边界

`mDNS` 和 UDP 只广播以下候选信息：

- 设备 UUID、展示名、监听端口。
- 配对密钥经域分离 SHA-256 后截取的 `domain_id`；不广播配对密钥本身。

发现信道不提供成员认证。伪造 `domain_id` 的设备最多成为候选，必须完成 TCP 认证握手后才能发送或接收应用帧；未经认证的 UDP 心跳不会进入 `known_members`。

每条 TCP 连接在读取任何可变长度帧前执行固定长度握手：

1. 服务端发送 `88 bytes` challenge，包含协议头、设备 UUID、随机 nonce 和 HMAC-SHA256。
2. 客户端验证 challenge，发送 `88 bytes` response，绑定双方设备 UUID、challenge 和客户端 nonce。
3. 服务端验证 response，返回 `56 bytes` acknowledgement。
4. 双方以完整 transcript 和配对密钥经 HKDF-SHA256 派生本连接独有的 session id、双向控制密钥和双向文件密钥。
5. 任一步骤失败即关闭连接，不读取长度前缀，不分配应用帧缓冲。

握手完整三步共用 `2s` 绝对总期限；每次 read/write 都只使用剩余时间，慢速 trickle 不能续期。单元测试使用内存构造或 loopback 连接，不通过放大生产超时来等待。新旧客户端互连会在该期限内失败，不会对称等待。

## 帧机密性与完整性

- 控制帧：`AES-256-GCM-SIV`。
- 文件 raw frame：`ChaCha20-Poly1305`。
- 加密为 `v5` 硬约束，设置迁移和 IPC 都会强制开启。
- 每连接独立派生密钥；连接 A 的密文不能在连接 B 重放。
- 控制帧 AAD 绑定版本、frame kind、session id 和严格递增序号。
- 文件帧 AAD 绑定版本、frame kind、session id、transfer UUID 和 chunk index。
- 解密后的 `source_device_id` 必须等于握手认证的 peer UUID。
- 文件流结束帧同时核对总字节数、chunk 数和完整 SHA-256。

当前群组密钥模型仍允许一个合法群组成员冒充另一个成员 UUID；它防止群组外设备加入，不提供群组内不可否认身份。若未来需要逐设备撤销、前向保密或成员不可冒充，应迁移到设备密钥对与经过认证的成员清单。

## 资源硬上限

| 边界 | 当前限制 |
| --- | ---: |
| 未认证 TCP 缓冲 | 固定握手消息；socket 缓冲约 `16 KiB` |
| 入站连接 | 总计 `16`，单来源 IP `4` |
| 同时接收文件 | `2` |
| 可移植控制 payload（文本 / HTML / RTF） | `8 MiB`，另加固定协议开销 |
| PNG / 文件 raw 分片 | `1 MiB` 单片，受认证并受 `max_item_bytes` 总量限制 |
| PNG 编码输入 | `80 MiB` 解码安全边界；超过时会明确拒绝，避免高压缩图片造成不可控内存占用 |
| 单帧读取 | idle `30s`；按实际帧长计算的绝对总期限 `8s..120s` |
| 整段文件 / PNG 接收 | idle `30s`；绝对总期限 `31s..30min`，按 `1MiB/s` 预算 |
| 文件/目录总大小 | 用户上限内，最大 `1000 MiB` |
| 归档条目 | `20,000` |
| 归档深度 | `32` |
| 顶层名称 | `256` |
| mDNS | `256` 个 resolved 事件，最多 `100` 个候选；后台/手动总预算 `900/2200ms` |
| 可达性探测 | 最多 `8` 个工作线程、`400ms` 总预算 |
| UDP 接收 | 每轮 `64` 包且最多 `3ms` |
| 设备缓存 | discovered/seen 各 `100`，known `256` |
| 最近事件 / 已应用 hash | `4096 / 1024`，另有 `120s / 10s` TTL |
| 日志内存 | `800` 条，每条最多 `8 KiB` |
| 日志文件 | `2 MiB` 后轮转一份 |

发送 peer 并发和失败重试同样有界；已成功 peer 不会因其他 peer 失败而重复收到同一轮重试。

## 文件与本地数据

- 线上 DTO 不包含 `PathBuf`；发送端本机路径与接收端 staging 路径永不序列化。
- 接收目录由本机在用户级应用缓存目录内生成，目录权限在 Unix 上为 `0700`；运行数据不落在仓库或 Syncthing 工作区。
- 运行目录和日志文件拒绝符号链接或非预期文件类型；Unix 日志以 `O_NOFOLLOW` 打开并拒绝多硬链接，Windows 打开后复核 reparse point 与文件类型。
- 归档拒绝绝对路径、`..`、反斜杠、链接、reparse point、特殊文件、重复路径和未声明顶层名称。
- 路径组件同时拒绝 Windows ADS、保留设备名和尾随点/空格，避免跨平台名称折叠。
- 发送端 fingerprint、估算和流式读取共享 no-follow 句柄身份校验；文件树在归档时重新完整计算 hash，不一致时不发送完成帧。
- 解包文件在 Unix 上使用 `0600`，目录使用 `0700`。
- 未完成、校验失败、过期或被新内容替代的 staging bundle 由 RAII/队列清理；完成写入剪贴板后最多保留 `8` 份且最长 `24h`，供用户继续粘贴。

## 配置与迁移

- 设置使用同目录临时文件、`fsync` 和原子替换；Unix 文件权限为 `0600`。
- 旧 6 位共享码升级时，原文件先备份为 `settings.legacy-v3*.json`，再生成新密钥。
- JSON 损坏或验证失败时，原字节先备份为 `settings.invalid-v4*.json`，再恢复安全默认配置。
- UI 只能提交 `SettingsUpdate` 中的用户字段，不能覆盖 device UUID、监听端口、轮询参数或安全开关；加密状态仅以只读徽标展示。
- 运行时重配失败会回滚旧设置和旧运行状态；保存成功后再更新内存 revision。
- autostart 与 JSON 分属 OS/后端两个提交点；IPC 报错后先回读核验全部用户字段，确定未提交才回滚 OS 状态，无法核验时明确报告未知状态与回滚结果。

## 升级与回退

- 升级：同一共享域的所有设备都升级到 `2.0.1/v5`；从 v4 升级时可保留同一 26 位配对密钥。
- 旧 `v3` 配置不会被静默删除，备份可用于回退取证。
- 回退：所有设备整体恢复到旧应用版本，并显式恢复对应的 legacy 配置备份。
- 禁止只回退单台设备后继续与 `v5` 混用；协议会 fail closed，但成员会表现为不可达。

## 仍需关注

- discovery 元数据仍可被同网段观察和伪造，只是不能越过 PSK 握手。
- 配对密钥泄露后需要在所有设备上轮换；当前没有单成员吊销。
- 当前 PSK 会话没有前向保密；密钥未来泄露时，历史抓包可能被重新派生解密。
- 已认证成员可制造有界但偏高的资源峰值；16 条连接与每连接 socket buffer/控制帧上限是性能和内存之间的取舍。
- 队列当前依赖 latest-marker 淘汰和 worker/连接并发形成实际边界，尚无独立容量常量；应作为防御纵深继续收敛。
- 文件名碰撞尚未覆盖 NFC/NFD 与完整平台 case-fold；当前会影响跨平台名称正确性，但不能用于目录逃逸。
- 应用读取系统剪贴板，操作系统账户内的其他应用仍属于本地信任边界。
- 本轮 macOS 与实际 Windows Syncthing 工作区均完成 Rust 全 target/feature check、测试和严格 Clippy；真实 Finder/Explorer、Office/浏览器粘贴仍需要发布前人工 smoke test。
